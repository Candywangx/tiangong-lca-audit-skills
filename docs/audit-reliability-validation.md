# 审核可靠性修复验证记录

本轮范围为修改方案 T1–T5；T6 分发依赖和 T7 模板同步尚未实施。所有运行验证使用脱敏样本、临时案件和本地工具，不操作真实平台或真实案件。

## 行为与兼容性

- 无效 Agent 判断和无效 source checks 保留原始记录及诊断，但不参与正式阻断或有效覆盖。其他独立有效阻断仍可导致不通过。
- 必审与豁免配置以规则 JSON 为唯一来源，模板、预检和完整审核动态读取。同一规则 ID 不再维护第二份必审表。自然语言适用性仍由 Agent/审核员判断。
- 正式审核会在案件范围内解析引用。旧 `:p3` 引用仍支持，但必须真实存在第3页；无页码文本不能证明页码。附加发现同样需要引用。引用格式的唯一规范见 Skill 的 input-contract.md。
- 模型以实际 TIDAS 参考实例、倍率和过程基准量解释目标，关联过程审核报告须与本轮快照、ID、版本匹配。非关键实例仍需基本过程证据，只免完整报告。历史报告无快照hash时须提供匹配的原semantic-context；缺证据时不能自动升级。索引规范以 input-contract.md 为准。
- `agent-findings validate --input ...` 未提供案件根时仅验证结构；使用 `--case-root` 或 `--review-id` 才能验证实际引用。历史记录缺引用、引用不存在、source 与 claim 不对应时须人工补充真实证据，不能自动编造迁移。
- 评测返回 `passed`、`failed`、`needs_manual_review`。CLI 对硬失败退出1，对需要语义复核退出2，只有已满足验收条件退出0。`--fail-under 0` 不会绕过硬失败或待复核；结论矛盾也不再依赖可选开关才能被发现。
- 评测的 `pointId` 区分问题身份。`evidenceGroups`、`judgmentGroups`、`suggestionGroups`、可选 `locationGroups` 为各字段独立匹配条件：组间 AND，组内替代词 OR。rule_id 仅筛选候选，建议中的关键词不充当证据。一条合并意见可以覆盖多个问题，但各点必须独立满足条件。
- `forbiddenIssuePoints` 定义特定样本已确认的误报；`judgmentExact` 可匹配独立分句中的完整断言。未知额外意见、无法匹配的同义表达进入待复核，不直接推定错误。旧历史案例仅有关键词/笼统建议时也进入待复核，不能冒充100%质量。历史 high/medium/low 表示旧优先级，不等于当前四类发现严重程度。
- 这些自动条件证明契约、定位或基准匹配有效，不证明原文语义真实。历史通过案例中的赞语也不能替代缺失的单位或模型证据。

## 已观测的反例

T1：缺证据阻断、混合有效/无效阻断、无效附加发现、无证据/来源source冲突，首次5项失败后修复通过。

T2：全部不适用、核心项强行豁免、合法例外缺引用、目录动态变更，首次4项失败后修复通过；另修复非字符串规则ID与未知数据集类型。

T3：缺失文件、假页码/块、越界路径、错误案件身份、source字段/来源不对应、无依据matched/conflict/not_applicable均有反例。保留合法文件、JSON空值指针、实际PDF页和解析块的正例；没有为通过测试放松定位校验。

T4：第一轮20项失败、1项通过，修复后21项通过；后续扩展至47项模型回归。独立复核关闭了“非关键实例完全没有过程数据仍通过”和“删除本轮快照、改指自洽旧报告仍通过”两个绕过。参考实例排后复用同一过程、无连接多关键实例、原始/包装TIDAS、错误版本/hash、局部审核和已证实结构阻断意见均有对应回归。合法单/双节点、同UUID不同实例、异UUID流连接及有基本证据的非关键实例保留正例。

T5：空规则ID意见满分、同规则重复覆盖、无建议、建议替代证据、通过含阻断等首次8项失败后修复。独立复核另发现并修复禁报断言藏在合并意见及阻断被低判为信息不足，均先观测失败。
