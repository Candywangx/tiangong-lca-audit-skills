# 专家名册绑定与专业匹配首轮验收

> 使用 superpowers:subagent-driven-development 实施和独立复核。用户已批准本轮名册绑定验收及一轮专业匹配盲测；不接网页、不执行分配、不新增自动化写入。

**Goal:** 用用户提供的专家 CSV 建立可追溯的本地名册和账号绑定，使用真实案件快照进行独立的专业推荐与盲评，并报告可用性与不足。

**Architecture:** 身份和资格由平台只读证据确认；专业适配由 Agent 读取原文判断。程序检查契约、引用、去重、候选资格和试验统计。结果先交用户确认，确认之后的分配是独立流程。本轮没有自动分配入口。

**Tech Stack:** Python、标准库 CSV/JSON、现有 requests 平台客户端、pytest、独立 Agent。

## Representation Decision

- Entity: 专家档案、平台绑定快照、专业推荐、盲评结果。
- Product role / consumers: 当前审核对话中的本地证据与人工确认材料，由 Agent、管理员和测试消费。
- Truth status: 名册资格来自用户材料；平台绑定仅证明本次可见账号及审核员资格；推荐不代表任命。
- Freedom level: 专业判断 F2（原文、理由、证据与缺口）；ID、输入摘要和只读绑定 F3。
- Representation: 不可变 JSON 快照与文件摘要；当前无需 SQLite、服务端或新的模型服务。
- Required evidence: 导入行号、原文、目录全分页完成证明、用户 ID 读回、案件快照和专业说明。
- Allowed mutations: 本地导入/只读同步、独立新运行和纠偏记录；不得覆写首轮盲测以提高成绩。
- Promotion: 经用户真实反馈与复测后再决定持久数据库和排序参数。
- Demotion: 输入不足或目录读取不完整时保留异常，不伪造绑定成功或凑足三人。
- Validation loop: 脱敏测试 → 真实只读绑定 → 冻结盲测输入 → 独立推荐和参考评审 → 统计与人工待确认清单。

## 首轮结果与边界

名册154行（入库116、未入库38），53位入库专家完成邮箱、审核员角色与ID读回核验。20个历史案件形成43个推荐配对，经独立复核37个有支持、6个有条件、0个无依据；8案给满三人。原始结果保持冻结，非人工金标准。

盲测发现的产品证据索引缺口已通过包含全部交换的 experts prepare 修复并回归；代码复核发现的源CSV变化与历史关联过程残留也已修复。结果及真实名单均在私有目录；公开汇总见 docs/expert-selection-validation.md。没有任何平台分配、权限修改、网页接入或GitHub推送。
